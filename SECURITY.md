# Security policy

## Reporting a vulnerability

Do not open a public issue containing a credential, private infrastructure detail, exploit against a real target, or unredacted audit evidence. Use GitHub private vulnerability reporting when available.

Include the affected version, reproduction conditions, impact, and a minimal sanitized proof. Do not perform testing against systems you do not own or have explicit authorization to assess.

## Scope

The public repository is an offline reference implementation. It does not contain live Hermes credentials, private profile state, raw audit logs, or an autonomous remediation channel.
